# Standalone predictive CFR benchmark

See [PredictiveCFR.md](PredictiveCFR.md) for solver formulas and API details. Run this standalone harness from the repository root with .NET 9 or a compatible newer SDK:

```powershell
dotnet build ACESimConsole/ACESimConsole.csproj -c Release
dotnet ACESimConsole/bin/Release/net9.0/ACESimConsole.dll --predictive-cfr-benchmark --self-test
dotnet ACESimConsole/bin/Release/net9.0/ACESimConsole.dll --predictive-cfr-benchmark --self-test-outcomes
dotnet ACESimConsole/bin/Release/net9.0/ACESimConsole.dll --predictive-cfr-benchmark --output C:\benchmarks\publication-cfr-1000 --iterations 1000 --checkpoint 100
```

The output directory must be new or empty. The command never calls the production launcher or its algorithm/report/cache save path. It does not open TeX or GUI tools, access the clipboard, write to cloud storage, or overwrite production reports/equilibrium caches. A failed run retains already flushed checkpoints; `completion.json` exists only after all selected runs finish. Start a new directory to rerun or resume selected case/method combinations.

The historical CSV defaults to `C:\Users\Admin\source\repos\endogenous-disputes-article\ReportResults\PREC010 output.csv`. On another machine pass `--historical-csv <path>`. Exactly one `Filter=All` row must match each selected historical publication case's full option name. Synthetic betting cases require no historical CSV and claim no matching historical outcomes. Mixed selections match only the historical subset. The harness preserves every matched cell as its exact source string, line number, file SHA256, and parsed E/runtime. It also hashes matching historical logs when the accompanying `Individual Simulation Results` folder exists.

For a short timing/evaluator smoke run:

```powershell
dotnet ACESimConsole/bin/Release/net9.0/ACESimConsole.dll --predictive-cfr-benchmark --output C:\benchmarks\cfr-smoke --cases baseline --methods legacy,pdcfr+ --iterations 5 --checkpoint 5 --no-outcomes
```

For configuration inspection without building a game tree or running iterations:

```powershell
dotnet ACESimConsole/bin/Release/net9.0/ACESimConsole.dll --predictive-cfr-benchmark --output C:\benchmarks\cfr-configuration --dry-run
```

To solve first and generate economic reports later, run with `--no-outcomes`, then load its saved candidate policies into a separate output directory. This performs no solving and validates the reconstructed game tree against the source configuration:

```powershell
dotnet ACESimConsole/bin/Release/net9.0/ACESimConsole.dll --predictive-cfr-benchmark --outcomes-from C:\benchmarks\publication-cfr-1000 --output C:\benchmarks\publication-cfr-outcomes --cases baseline --methods legacy,cfr+,pcfr+,dcfr+,pdcfr+
```

Select only cases and methods present in the source directory. The postprocessor records the source provenance/profile hashes. Reports whose best and final policy profiles are identical are computed once and reused.

Available flags:

| Flag | Meaning |
| --- | --- |
| `--output <directory>` | Required, new or empty directory. |
| `--methods <comma-separated>` | Default `legacy,pcfr+,dcfr+,pdcfr+`; also supports `cfr+`. |
| `--cases <comma-separated>` | Default `baseline,fee,damages,risk`; optional `hard-indeterminacy` and the four synthetic betting cases below must be selected explicitly. |
| `--iterations <positive integer>` | Default 1000; complete iterations, with no early convergence stopping. |
| `--checkpoint <positive integer>` | Default 100; final iteration is always evaluated even when not a multiple. |
| `--legacy-flavor fast\|regular` | Default `fast`, double precision. |
| `--historical-csv <path>` | Historical source CSV to read and hash. |
| `--outcomes-from <directory>` | Replay final/best saved policies from an existing benchmark, writing into the separate `--output` directory. |
| `--no-outcomes` | Skip the final/best policy economic reports. Reports are otherwise generated by exact path enumeration. |
| `--no-gebr-crosscheck` | Skip the independent first-checkpoint GEBR check. Default checks both policies and both players. |
| `--dry-run` | Write configuration/provenance only. |
| `--self-test` | Run argument, case reconstruction, checkpoint schema, historical CSV quotation/uniqueness, and provenance tests. |
| `--self-test-outcomes` | Also train a tiny nonuniform policy, roundtrip its saved current/average profiles, and compare all selected native full/restricted report cells for both policies. |

## Game and methods

The four cases use full publication grids (8 signals, offers, precaution power levels, and precaution levels), one bargaining round, collapsed chance decisions, P/D/court liability noise 0.2, and `PredeterminedAbandonAndDefaults=false`. They start with an explicit precaution-negligence seed and apply the endogenous launcher's risk, costs, fee, damages, liability-threshold, and precaution-cost transformations. This avoids current default drift to a different game and a grid of 10/noise of 0.35. Court damages noise remains the seed's 0.15.

| Case | Exact option name |
| --- | --- |
| baseline | `Risk Neutral CM 1 FSM 0 DM 1 LT 1 UPC 1E-05` |
| fee | `Risk Neutral CM 1 FSM 1 DM 1 LT 1 UPC 1E-05` |
| damages | `Risk Neutral CM 1 FSM 0 DM 2 LT 1 UPC 1E-05` |
| risk | `MODRA CM 1 FSM 0 DM 1 LT 1 UPC 1E-05` |
| hard-indeterminacy (optional) | `Risk Neutral CM 4 CN High Indet UPC 1.2E-05` |

The optional `hard-indeterminacy` case retains the same publication grid and signal noise 0.2. It applies risk neutrality, costs multiplier 4, `CourtNoiseInfo(0.2, true, 0.5, "High Indet")`, and unit precaution cost `1.2E-05` to the seed, in that order. Court indeterminacy is the probit decision scale 0.5; court signal noise remains 0.2. Seed defaults retain damages multiplier 1, no fee shifting (`LoserPays=false`), and liability threshold 1. This case does not change the default four-case selection. Inspect its exact historical CSV/log match without solving:

```powershell
dotnet ACESimConsole/bin/Release/net9.0/ACESimConsole.dll --predictive-cfr-benchmark --output C:\benchmarks\hard-indeterminacy-configuration --cases hard-indeterminacy --methods legacy,cfr+,pcfr+,dcfr+,pdcfr+ --dry-run
```

## Synthetic betting challenges

Select `bet-1-cost-1`, `bet-1-cost-4`, `bet-5-cost-1`, or `bet-5-cost-4`. The first number is the equal challenged/challenger damages multiple; the second is the litigation cost multiplier. These use `LitigGameSideBet` pretrial challenges, with action 1 meaning challenge and action 2 meaning no challenge. Each party chooses privately after bargaining and before court. If at least one challenges, the trial loser transfers the stake times damages to the winner in addition to normal damages; there is no extra transfer without a trial. Running chip side bets remain disabled.

The mechanism and stakes are anchored to the `SideBet` (1/1) and `SideLarge` (5/5) regimes in commit `c28d03a5`, `ACESim4/Games/MyGame/MyGameRunner.cs`. This is a new experiment on the current ordinary exogenous dispute model, adapted to one perfect-recall bargaining round from the historical three limited-recall rounds. Modern signal and court implementations also differ; it is not a replay of that historical simulation or a publication-case match.

Parameters are explicit: true-liability prior 0.5 and liability-strength noise 0.5; 10 strength points, 10 signals, and 11 endpoint-inclusive offers (0, 0.1, ..., 1); P/D/court signal noise 0.3; initial wealth 10 each, damages 1, risk-neutral utilities; filing/answer costs 0.05 each, trial costs 0.15 each, bargaining cost 0.10 per party, multiplied by 1 or 4. One simultaneous bargaining round reveals offers, includes agreement-to-bargain and quit decisions, and retains file/answer choices. Chance decisions are collapsed, alternative endings are not collapsed, and warm starts and fee shifting are disabled. Missing pretrial information sets cause a run to fail.

```powershell
dotnet ACESimConsole/bin/Release/net9.0/ACESimConsole.dll --predictive-cfr-benchmark --output C:\benchmarks\betting --cases bet-1-cost-1,bet-1-cost-4,bet-5-cost-1,bet-5-cost-4 --methods legacy,cfr+,pcfr+,dcfr+,pdcfr+ --iterations 1000 --checkpoint 10
```

Provenance schema 3 labels these `synthetic-counterfactual`, records the mechanism anchor and full parameters, and stores no historical match. Synthetic-only runs do not read the historical CSV. Original default selections remain unchanged.

Betting outcome reports retain native `All`, `DisputeArises`, and `Tried` rows, adding harness-only `PChallenge`, `DChallenge`, `AnyChallenge`, and `BothChallenge` columns. These indicate pretrial challenges rather than running-chip bets. `All` challenge probabilities include trial reach; `Tried` conditions on reaching trial. The structured `challenges` object records exact trial reach and unconditional/conditional challenge probabilities using cached-tree reach, checked against formatted native report cells within `2e-6`. Conditional values are JSON null at zero trial reach; selected `Tried` challenge cells are then blank rather than meaningful zeros.

Each betting run also writes `challenge-information-sets.json` (fixed ordered identities) and `challenge-policies.jsonl.gz` (one compact JSON line per checkpoint and current/average profile). Each line contains `iteration`, `profile`, exact aggregate `diagnostics`, and `action1Probabilities` in metadata order. This trace avoids Bayesian outcome replay at checkpoints. Per-information-set probabilities are unweighted and may describe unreachable states; a large swing alone does not establish on-path cycling. Compare current/average root deviation and trial-conditioned diagnostics too. Raw and normalized deviations both matter because stake and cost changes alter terminal utility ranges.

The historical publication cases reconstruct published parameters on the current game model rather than reproducing historical results bitwise. All methods start at uniform policies with zero regret and strategy accumulators, with no solving warmup. The legacy method preserves modern `GeneralizedVanilla` simultaneous, reach-normalized updates, geometric 0.99 regret discounting, and perturbation 0.001 decaying to zero. Historical code also enabled opponent probability pruning below 1e-4, which modern legacy code disables; the benchmark uses full traversal. Canonical methods use standard counterfactual regret updates with alternating player updates. Thus a legacy comparison does not isolate prediction's effect. Compare `pcfr+` against optional `cfr+`, or `pdcfr+` against `dcfr+`, to examine more closely matched method families; their published averaging/discounting defaults still differ and are recorded in configuration.

## Files and interpretation

- `provenance.json`: command, runtime/OS, source commit and dirty state, tracked diff hash, relevant source hashes, console/base assembly hashes, all settings, case identities/hashes, exact historical CSV rows, historical log hashes, and comparison caveats.
- `checkpoints.csv`: one row for each current/average policy at every checkpoint, including each player's raw and normalized deviation, score ranges, half sum, maximum, elapsed times, and independent BR error when checked.
- `summary.json` and `summary.csv`: final and best observed policies separately. JSON also contains selected outcome rows and first observed checkpoint meeting each maximum-deviation threshold (0.01, 0.001, 0.0001, 0.00001, 1e-7, 1e-8, 1e-9), plus secondary E threshold 0.000005. These are observed checkpoints, not exact crossing times.
- Each case/method directory contains its `configuration.json`, `summary.json`, `final-profile.json.gz`, `best-current.json.gz`, `best-average.json.gz`, and economic outcome CSVs for each final/best current/average policy. Compressed profiles preserve full double precision probabilities and information set identities; they are usable candidate policies, not solver-resume snapshots.
- `completion.json`: completion time and selected/completed run counts.

For two players, the historical `Exploitability` column is `E_half_normalized = (deviation0/range0 + deviation1/range1)/2`. A unilateral deviation is best-response utility minus the selected policy's utility, holding the other player's policy fixed. `max_normalized` is the larger individual normalized deviation. Each range is the player's full terminal utility maximum minus minimum. The harness retains these ranges and raw deviations; it never rounds or prunes the evaluated policy. The first checkpoint independently compares accelerated BR utility with GEBR (absolute tolerance 1e-8). Profile simplex, finite metrics, and positive score ranges are checked.

The average policy means normalized cumulative strategy mass, including every nonzero probability. Legacy training stores a second average-policy cache that thresholds small probabilities. At a checkpoint, the harness temporarily synchronizes that cache to the unrounded cumulative policy for evaluation, then restores the original cache before training resumes. Saved profiles and economic replay use this same unrounded policy. Provenance schema version 2 explicitly records this convention; earlier experimental legacy checkpoint files that certified the thresholded cache are superseded.

Economic reports retain the native production report's exact column evaluators, `All` and `DisputeArises` filters, denominators, Bayesian latent-state expansion, and existing numeric formatting. They omit unrelated cells. The benchmark uses synchronous path processing so replay/report errors propagate directly. It checks total path probability and independently sums cached terminal utilities, requiring agreement with the same profile's exact BR evaluator baseline utilities (absolute tolerance 1e-8); the outcome JSON preserves both utility vectors and their maximum difference. The nonuniform saved-profile self-test also checks that the full and restricted report cells match.

The predeclared main acceptance threshold is maximum individual normalized deviation <=1e-5; E_half<=5e-6 is a secondary threshold. A tiny root deviation alone says little about economic agreement because disputes occur with probability around 1e-4. Compare precaution, filing, settlement, trial, and welfare outcomes too. `Filter=All` means the ex ante population; `Dispute Arises` conditions on a dispute. Preserve those denominators when comparing rows.

Historical saved outcomes were reported using `CurrentProbability`, while historical `Exploitability` evaluated the final average policy, which can differ from the best historical checkpoint (fee best at 600; risk best at 400). The new final/best current/average outputs explicitly keep those selections aligned. Historical `Calculation Time` includes work beyond solving; compare it with new wall time cautiously. New setup, iteration-only solve, checkpoint evaluation, outcome-report, and total wall times are separate. Serialization and tree-count/configuration work contributes to wall time but not solve time. Run methods sequentially on the same machine for the most interpretable timing comparison; concurrent runs contend for resources.
